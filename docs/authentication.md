# 登录与会话

第一版使用单管理员账号，管理现有全部工作空间。默认登录有效期为 7 天，自本次登录起计算，刷新页面、关闭再打开浏览器、重启服务器不会延长或清除有效会话。

## 初始化管理员

先安装依赖，使用交互式命令设置密码（至少 12 字符）：

```sh
python -m pip install -r requirements.txt
python auth.py --db /persistent/private/auth.db --username admin
```

密码不会出现在命令行参数或输出中。认证数据库只保存 scrypt 密码哈希、随机盐、会话令牌的 SHA-256 哈希和限速记录，不保存明文密码或原始会话令牌。
认证数据库必须持久化，应用用户应有读写权限。它独立于笔记数据库，不包含在笔记的 ZIP / .plbackup 中；需要另行安全备份，丢失后可重新建立账号，但所有旧登录会失效。重置密码不会修改笔记或数据加密密钥。

## 部署配置

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `PROCESS_LOG_AUTH_ENABLED` | `1` | 正常 server.py 启动默认要求登录；`0` 仅用于明确无需认证的本地测试 |
| `PROCESS_LOG_AUTH_DB` | 数据目录下 `auth.db` | 认证数据库路径，须事先初始化 |
| `PROCESS_LOG_SESSION_DAYS` | `7` | 登录有效期，允许 1–30 天 |
| `PROCESS_LOG_COOKIE_SECURE` | `1` | 默认只在 HTTPS 发送 Cookie；显式设为 `0` 可用于本机或用户明确选择的局域网 HTTP |
| `PROCESS_LOG_TRUSTED_PROXIES` | 空 | 可信反向代理的精确 IP，逗号分隔，禁止填写任意客户端地址 |

生产部署推荐 HTTPS。仅启用 Secure Cookie 并不会让 Python HTTP 服务变成 HTTPS，需要可信反向代理终止 TLS。HTTP 兼容模式下密码和 Cookie 都没有传输加密保护。
使用反向代理时保留正确 Host，配置 `PROCESS_LOG_ALLOWED_ORIGINS` 为浏览器实际访问的完整 HTTPS 来源。代理必须覆盖或正确追加 `X-Forwarded-For`，后端仅接受可信代理访问；应用从可信代理链右侧提取客户端地址，其他请求的伪造头不会影响限速。
不要让没有认证配置的旧容器或另一个监听端口继续对外提供数据。

开发测试通过 `make_server(..., auth_db=None)` 显式保持无认证的隔离环境；这与 `server.py` 正式入口默认启用认证不同。浏览器回归使用单独的固定测试账号和临时数据，不能用于生产。

## 登录保护

- 所有笔记读取/修改、附件、Markdown 导出、完整备份与恢复 API 都检查服务端会话。
- 静态界面资源、登录状态/登录入口及不包含业务内容的健康检查公开。
- Cookie 使用 HttpOnly、SameSite=Strict、Path=/，不写入 localStorage；默认 Secure。
- 同客户端 15 分钟内 10 次失败后暂时限速；存在全局失败上限。反向代理须按上面的可信代理配置区分客户端。
- 会话到期由服务器检查；服务器重启后保留有效会话。每个账号最多 50 个有效会话，超过后撤销最旧会话。
- 主动退出撤销当前会话并清理当前浏览器本应用的本地正文草稿；退出前先保存当前笔记，保存失败时不直接退出。
- 其他标签页收到退出通知后遮挡正文并要求重新登录，保留其未保存输入。
- 会话过期不刷新编辑页。重新登录后可重试保存；页面/电脑关闭仍遵循原有浏览器草稿机制。
- 修改密码验证当前密码并撤销所有会话。无法登录时管理员可交互式重置：

```sh
python auth.py --db /persistent/private/auth.db --username admin --reset
```

不提供公开注册、网页找回密码、多用户权限分配或分享链接。登录并不撤回已经下载的图片、PDF、备份或用户已看到的内容。
