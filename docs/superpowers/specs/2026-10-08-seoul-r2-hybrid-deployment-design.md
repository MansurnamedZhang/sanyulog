# 三余记首尔 Docker 与私有 R2 媒体部署设计

日期：2026-10-08。状态：用户已批准设计，实施计划待审核。目标域名：`notes.896364.xyz`。

## 1. 目标与边界

将“三余记 · Sanyu Notes”部署为首尔服务器 `43.131.245.43` 上的独立 Docker 服务，并把本工具的附件密文同步到 Cloudflare R2。公网用户经 HTTPS 登录后仍使用原有笔记、账号、密码和服务端加密；不把私有附件设为公开对象，也不把数据库、认证库、配置和根密钥上传到 R2。原局域网实例 `172.16.240.13:8765` 保留为可恢复的回退副本，不删除其容器、数据或备份。

这是“首尔 Python 应用 + PostgreSQL + 私有 R2”的混合部署，不是 Workers/D1 全托管迁移。当前仓库 `docs/cloudflare-deployment.md` 描述的 Workers/D1 路线不在本阶段范围内。

## 3. 选定架构

浏览器 `https://notes.896364.xyz` → Cloudflare DNS/代理 → 首尔宿主机 Nginx（TLS）→ 仅绑定 `127.0.0.1:18765` 的应用容器。应用使用专属 PostgreSQL 容器与持久卷；认证库、原始 32 字节加密密钥和附件本地镜像用独立受限挂载保存。不得复用或修改其他应用的数据库、卷、Nginx 站点或端口。

新建专用私有 R2 桶 `sanyulog-media`；不启用 `r2.dev` 公共开发 URL，不连接对象直出域名，不设置公共读权限或浏览器 CORS。服务器使用仅限该桶对象读写的 R2 API 凭据；凭据以受限只读文件挂载到容器，不能写进 Git、镜像、Compose 明文环境、前端、日志或聊天。若无法安全创建并交付该凭据，则停止 R2 实施并请求用户在 Cloudflare 控制台创建；不得借用其他项目的宽权限密钥。

R2 对象 key 为 `v1/<storage_id>/<plaintext_sha256>`，其中 `storage_id` 由已认证会话决定，不能由浏览器指定。对象内容保持现有 `StorageCipher` 的 AES-256-GCM 密文信封，R2 Content-Type 固定为 `application/octet-stream`。数据库中的附件 ID、文件名、MIME、大小、哈希及笔记引用格式保持兼容。相同哈希在不同账号分区为不同对象；仅 R2 key 前缀不足以授权访问，所有读取都先经过应用会话、账号数据区和数据库记录校验。

## 4. 媒体读写、删除与恢复

- 上传：沿用 25 MiB 单文件上限。先校验内容哈希并原子写入本地密文，再上传同一密文至 R2、核对对象大小和服务端保存的 SHA-256 元数据，最后提交原有数据库附件记录。R2 失败时不向用户报告上传成功；可留下不可访问的暂存孤儿供受限清理，不改变已有记录。重试必须幂等，不能覆盖哈希相同但内容不同的对象。
- 读取：先查当前账号的附件记录，再从 R2 取密文、解密并验证明文 SHA-256 与记录大小；R2 失败、对象缺失或校验失败时仅可从同账号本地密文回退，回退内容也必须重新验签并记录降级告警。两个副本都无法验证则拒绝返回内容。不得重定向到 R2 公共 URL，也不得生成可绕过会话的长期下载链接。
- 预览：继续只允许安全图片 MIME 内联；为受控音频/视频预览增加明确的 MIME 白名单、内容检查和单区间 `Range` / `206` / `416` 响应。其他附件保持下载，不执行 HTML/SVG/脚本。既有 20 个附件均为图片；音视频 Range 用隔离测试文件验证，不向生产笔记注入测试数据。无需转码。
- 删除：应用接口立即撤销数据库引用和访问。仅在同一账号内确认没有其它记录引用该哈希后清理对象；R2 或本地物理删除失败必须可重试、可审计，不能让已删除附件重新经 API 被访问。任何清理不得跨账号 key、不得扫描删除其它桶。
- 备份：本地密文镜像仍是现有 `.plbackup` / PostgreSQL 备份与恢复的完整来源，因此 R2 故障不能使原有备份不可用。恢复先在隔离目录验证备份、数据库和全部附件，再恢复本地状态并对 R2 做幂等对账；R2 未核对完不得声称云端媒体恢复完成。保留原密钥、信封格式、附件 ID 和账号映射，禁止生成新密钥覆盖旧数据。

Cloudflare 官方支持通过私有桶的 S3 兼容 API、`boto3` 和 `region_name="auto"` 服务端读写；不需浏览器直连 R2。[boto3 文档](https://developers.cloudflare.com/r2/examples/aws/boto3/)、[R2 API 凭据](https://developers.cloudflare.com/r2/api/tokens/)

## 5. 迁移与切换顺序

1. 重新核对源仓库精确提交、对应 GitHub Checks、源容器健康、账号/会话/笔记/附件清单，以及首尔资源、端口、Nginx 和 DNS。创建私有 R2 桶与最小权限凭据前，再核对目标账号和桶名无冲突。
2. 在隔离环境完成 R2 适配的单元和端到端测试：加密兼容、双写故障、R2 读取与本地回退、跨账号拒绝、上传/删除幂等、备份/恢复、预览与 Range。通过精确提交的 CI 后制作可追溯镜像；不得先用生产数据验证新代码。
3. 首尔先部署独立数据库、应用与 loopback 端口，用本机 Host/Origin 校验做内部 HTTP 测试。可提前为证书申请创建 `notes.896364.xyz` DNS，但公网入口在完成迁移验收前只返回维护页，不接收用户写入；此时不改源实例。用隔离测试数据完成首尔和私有 R2 联调，并在启用真实应用代理前验证 HTTPS 证书。
4. 约定短暂维护窗口并停写源容器，仅对本工具做一致性快照：PostgreSQL 自身数据库、完整 `auth.db`（包含停用账号与会话）、全部账号本地附件、配置/Compose、原始 `storage.key`。备份须受限、可校验，且不能把密钥值输出或上传到 R2。
5. 经 SSH 安全复制到首尔受限目录，恢复到隔离卷和独立数据库；按数据库引用生成精确媒体清单，仅将本工具当前有效附件密文上传到专用 R2 桶。逐对象核对源密文 SHA-256、目标对象大小与读回 SHA-256，再用原密钥验证明文哈希、长度和引用。没有初始化 schema 的停用账号仍保留其认证记录。
6. 验证首尔用户登录、未登录 `401`、错误 Host/Origin 拒绝、跨账号附件拒绝、账号/会话/笔记/附件数量与内容摘要一致、图片预览、备份恢复、私有桶不可匿名读取以及所有既有服务健康。确认后才把 `notes.896364.xyz` 指向首尔。域名变更使浏览器 Cookie 不随源站搬迁，用户需重新登录；密码哈希与服务器会话记录保持原样。
7. 源容器、数据库和备份一律不删除。正式切换后应防止源实例继续接收写入而形成双主；默认保持源容器停止但可立即按回滚步骤启动。若用户要求源站持续可读，需要另行设计只读模式，不能让两个站点同时可写。

## 6. 回滚与失败边界

切换前任何构建、R2、数据或 HTTPS 校验失败：保持旧实例及其数据，停止或隔离首尔新服务，不更改 DNS。切换后若首尔已产生新写入，**不得直接启动旧实例并把 DNS 切回**，否则会丢失新增数据；先停写首尔、导出并核对增量，再决定合并或显式接受数据回退。回滚保留首尔数据库卷、R2 桶和受限备份供调查，不运行 `docker compose down -v` 或删除桶。

所有会改变 DNS、运行容器或上传对象的步骤都应记录时间、精确提交、镜像摘要、数据清单、备份位置和可恢复的原配置；仅在本工具范围内操作。旧站与其它 Nginx 站点、Docker 服务、Cloudflare 桶不做清理。

## 7. 验收与非目标

验收需提供：实际 HTTPS 地址；精确 Git 提交与通过的 Checks；首尔容器/数据库健康、Nginx 与 TLS；未登录和跨账号保护；迁移前后账号（含停用）、会话、项目、笔记、附件数及内容摘要；R2 对象清单、数量、大小与 SHA-256；受控图片及音视频测试预览/Range；备份及恢复验证；源站和首尔其它服务健康；明确回滚路径。区分“创建了资源”“传完文件”“可用”“完成验收”，不能只靠桶内对象数量宣布完成。

本阶段不做 Workers/D1 全托管、公开视频桶、公共对象域名、媒体转码、超过现有 25 MiB 的单文件上传或跨站双向同步。R2 与本地双副本不是高可用数据库；数据库、认证库和根密钥的异机备份另行受控保存。
