# 过程簿 · Process Log

个人使用的本地过程记录工具。适合 LoRA 训练、工作流调试、软件排错和日常研究。中文界面，支持多账号独立空间、管理员创建账号、7 天免重复登录和服务器加密保存。默认使用 SQLite，也支持 PostgreSQL。运行前需安装 requirements.txt 中的依赖。

## 启动

首次运行先安装依赖并初始化账号；完成后可双击 `start.cmd` 启动。本机 HTTP 需按下面设置 Cookie 兼容模式，服务器推荐 HTTPS。

也可以在此目录运行：

```powershell
python -m pip install -r requirements.txt
python auth.py --db data/auth.db --username admin
$env:PROCESS_LOG_COOKIE_SECURE = "0" # 仅本机 HTTP；HTTPS 保持默认值 1
python server.py
```

需要 Python 3.12 或更高版本。若端口被占用，使用 `python server.py --port 8766`，再访问对应端口。停止服务按 Ctrl+C。默认只监听本机。局域网 PostgreSQL 部署见下文。

## 像 Notebook 一样持续记录

1. 新建笔记本，写下标题。首次使用会先创建项目。
2. 直接在单元格内开始写。支持 Markdown 正文、代码、日志原文、图片/附件、独立表格五种类型，同一个笔记本可自由混排。
3. 顶部工具栏在当前单元后插入，底部按钮继续追加；两个单元格之间的 `＋` 可在中间插入。
4. 用每格右上角的箭头调整顺序，`×` 删除单元格。底部可撤销最近一次删除。
5. Markdown 格默认以「所见即所得」编辑，点击顶部按钮可手动切换为「源码」。点击别的块不会自动改变模式。可以直接编辑排版后的标题、文字、列表和表格；截图仍可粘贴或上传。
6. 状态、标签、参数、目标和复盘收在「属性与实验配置」中，可选填。搜索覆盖笔记本正文和元数据，仍支持模板、关联、对比和 Markdown 导出。

代码单元仅记录和展示代码，不执行 Python。运行输出可放入相邻的日志格。代码和日志保留原始空格、缩进与换行。

## 自动保存与快捷键

源码模式的「表格」可选择数据行数和列数插入模板。所见即所得模式直接插入可编辑表格，光标放入表格后可用下方工具增加或删除行列。表格中 Enter 换段、Shift+Enter 换行、Tab 切换单元格；普通多段文字粘贴留在当前格。独立 CSV 表格保持原有操作。

从 Excel 或其他电子表格复制多个单元格，粘贴到 Markdown 编辑框会自动转换为表格（第一行作为表头）；支持空单元格、引号内换行和竖线内容。代码和日志单元格保持原始粘贴内容。

Markdown 单元格顶部提供加粗、斜体、标题、列表、行内代码、代码块、行内公式和独立公式按钮。源码模式选中文字后点击可包裹选区；所见即所得模式直接应用格式。公式按钮打开 LaTeX 编辑框，点击已排版的公式也可以修改。

LaTeX 公式使用 `$x^2$` 或 `\(x^2\)` 表示行内公式，使用独占行的 `$$` 或 `\[` / `\]` 表示独立公式，例如：

```latex
$$
\mathcal{L}=\frac{1}{N}\sum_{i=1}^{N}(y_i-\hat{y}_i)^2
$$
```

切换到所见即所得后显示排版公式。代码块和行内代码中的公式保持原文；公式语法错误会显示原文供修改。公式使用随应用分发的 KaTeX（`static/vendor/` 含版本与 MIT 许可证）生成 MathML，无外部 CDN 请求，需要支持 MathML 的现代浏览器。

- 输入停止约 0.8 秒后自动保存到本地数据库，标题下方显示保存状态。
- 源码模式 `Shift+Enter`：保存并进入下一单元格，没有下一格时自动追加文本格；所见即所得与独立表格内保持换行。
- `Ctrl+S`（Mac 为 Cmd+S）：立即保存。
- 代码/日志格内 `Tab`：插入四个空格。
- 切换笔记本或导出前会先保存。失败会阻止切换并保留浏览器草稿，可重试。
- 多窗口发生版本冲突时不会覆盖数据；可下载当前 JSON 草稿，然后重新载入已保存内容。草稿下载用于保全内容，不是完整数据库备份。

保存期间可以继续输入，新内容会接续保存，不会被旧请求覆盖。未保存草稿暂存在当前浏览器，不包含在完整备份内；清理浏览器数据或更换浏览器可能清除草稿。

## 图片与附件

选择「图片 / 附件」单元格上传，或在任意单元格内直接粘贴截图。上传完成后图片显示在正文，其他文件显示下载链接。单文件最大 25 MB。单个笔记本最多 2000 格，正文数据最多约 1.5 MB，单格最多 50 万字符；较长日志建议作为附件保存。

超过新版长度或数量上限的旧记录仍能保存现有正文、调整顺序及缩短内容，并可完整备份恢复；继续增加内容时请新建笔记本。

「移出此格」只取消这处展示，文件仍保留在底部的「全部附件」中，可以重新插入。图片预览只请求本机资源，附件不进行内容解析。

## 旧记录升级

首次启动新版时，会在 `data/backups/before-notebook-*.zip` 保存升级前备份，然后把旧时间线按原始顺序转换为 Markdown 单元格，原分类作为小标题保留。原附件整理为附件单元格，参数和复盘仍在属性区。转换可重复启动，不会生成重复单元格。原始时间线表保留，新版正文以 Notebook 单元格为准。原来未发送的时间线草稿也会在打开对应笔记本时带入。

## 保存位置与备份

- `data/process.db`：SQLite 数据库，包含项目、笔记本单元格、参数、模板和附件索引。
- `data/attachments/`：原始附件，使用内容哈希命名。
- `data/backups/`：每次恢复前自动生成的完整 ZIP 快照。

「完整备份」导出当前所有已保存数据和被引用的附件；「从备份恢复」验证完整性后替换现有数据，并先保存恢复前快照。备份与恢复均限制原始数据库和附件合计不超过 250 MB；超过上限时会明确拒绝，现有数据保持不变。SQLite 模式数据量较大时可在停止服务后复制整个 `data` 目录作为文件备份。PostgreSQL 模式需同时备份数据库和附件目录。应定期将备份复制到另一块磁盘。Markdown 导出包含单条记录、时间线及附件清单；原文件请通过完整备份带走。

删除记录或附件会移除数据库中的引用；附件实体暂不主动清理，避免误删和恢复竞争，因此磁盘占用不会立即下降。完整备份只包含仍被引用的附件。无云同步、无训练日志自动采集，也不连接模型服务。

如需更换数据目录：`python server.py --data D:\MyProcessData`。恢复失败时现有数据库保持不变；如果磁盘空间不足，请腾出空间后重试。

## 开发与验证

```powershell
python -m unittest discover -s tests -v
node --test tests/notebook.test.mjs
npm run check
```

后端采用 Python 标准库 HTTP 服务与 SQLite，前端为原生 HTML、CSS、JavaScript。`store.py` 负责持久化和备份，`server.py` 提供本地 API，`static/` 为界面，`notebook-core.mjs` 实现保存队列与 Markdown 渲染，`notebook.js` 实现单元格编辑器，`tests/` 为真实临时数据与 HTTP 集成测试。运行本工具不需要 Node.js。

## Linux PostgreSQL 部署

可使用仓库中的 `Dockerfile` 构建应用镜像，连接自行管理的 PostgreSQL。数据库、附件和备份目录应持久化到容器之外。部署配置及数据库凭据通过环境变量提供，不写入源码。

手动运行时先安装 `requirements.txt`，设置 `DATABASE_URL`、`PROCESS_LOG_HOST`、`PROCESS_LOG_ALLOWED_ORIGINS`（逗号分隔完整来源）及 `PROCESS_LOG_ATTACHMENTS`，然后运行 `python server.py`。局域网监听需显式配置允许来源，Host/Origin 检查继续生效。

本应用没有登录认证，仅适用于可信局域网，能访问此端口的用户可读写记录。请勿直接发布到公网。代码单元不执行代码。

完整 ZIP 备份与 SQLite 模式互通：SQLite 文件仅作为备份交换格式。恢复会替换当前应用数据库内容，恢复前自动保存快照；大数据集请停写后配合 `pg_dump` 和附件目录做一致备份。应用 ZIP 备份仍有 250 MB 上限。

PostgreSQL 测试需提供专用、可清空的 `PROCESS_LOG_TEST_DATABASE_URL`，切勿指向生产库，再运行 Python 测试命令。

### 独立表格与 CSV

工具栏的“＋ 表格”创建独立表格单元格，可编辑表头及数据、增加或删除行列。第一行为表头，每页显示 50 行，最多 1000 行数据、50 列。支持导入 CSV/TSV（UTF-8 或 GB18030/GBK），导入前会确认替换当前表格。单格支持回车换行和粘贴多段文字，保留空段、逗号与引号。可从 Excel 粘贴区域（制表符或表格剪贴板格式）；区域粘贴从当前格开始覆盖。纯文本多行内容留在当前格，CSV 数据请通过“导入 CSV / TSV”载入。导出 CSV 带 UTF-8 BOM，保留逗号、双引号、多行内容及空值。表格随笔记自动保存并包含在完整备份中，Markdown 导出也包含表格。

### 列表与子列表

在 Markdown 单元格选中多行文字，点击“• 列表”或“1. 列表”，会将选中的完整行逐行转换成无序或有序列表；未选中文字不变，空行保留。再次转换会替换已有标记。选中需要作为子项的行，点击“→ 缩进”增加一级（4 个空格），点击“← 缩进”恢复上一级。已有列表可继续嵌套；子项应放在父项之后。未选择文字时，工具作用于光标所在行。预览支持有序、无序混合嵌套。

### 多工作空间与竖屏

左侧可切换、新建和重命名工作空间。现有项目自动归属默认空间；项目设置中可更改所属空间，笔记和附件随项目显示。删除空间前需移出项目，默认空间保留。空间用于分类组织，不是独立账号或权限隔离；模板共享，完整备份与恢复覆盖全部空间。切换空间前自动保存当前笔记。

窄屏或竖屏采用单列布局：点击“工作空间”展开导航，打开笔记后隐藏记录列表，点击“返回列表”继续浏览。编辑工具栏自动换行，代码及宽表格可横向滚动。

## 所见即所得编辑器构建

正文仍以 Markdown 保存，单纯切换模式不会重写源码；在所见即所得中修改后会生成规范 Markdown（表格内换行以 `<br>` 保存）。编辑器资源随应用分发，不依赖外部 CDN。开发时修改 `src/rich-editor.js` 后运行 `npm run build:editor`，提交生成的 `static/vendor/rich-editor.js` 与许可文件。CI 会检查构建产物一致性，Docker 直接使用已打包资源，不需要 Node.js。
